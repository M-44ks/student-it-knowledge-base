Git i GitHub (WARP)

System kontroli wersji i platforma do współpracy.

Nawigacja

  • Strona główna
  • Terminal Bash (UKOS)
  • Narzędzia .NET (PRG1)

Procedura pracy (Workflow)

  1. Synchronizacja: Pobranie najnowszych zmian z repozytorium (git pull).
  2. Branch: Utworzenie nowej gałęzi na swoje zadanie (git switch -c).
  3. Zmiana: Edycja plików w edytorze kodu.
  4. Commit: Zatwierdzenie wprowadzonych zmian (git add i git commit).
  5. Push: Wysłanie gałęzi na serwer GitHub (git push).
  6. PR (Pull Request): Zgłoszenie zmian do weryfikacji i scalenia.

Tabela poleceń

Podstawowe polecenia Git
Polecenie Opis
git clone Klonuje zdalne repozytorium na dysk lokalny.
git status Pokazuje stan repozytorium i śledzonych plików.
git add Dodaje pliki do poczekalni (staging area) przed commitem.
git commit Zapisuje zmiany z poczekalni w historii repozytorium.
git push Wysyła lokalne commity do zdalnego repozytorium.
git pull Pobiera i scala zmiany ze zdalnego repozytorium do lokalnego.
git fetch Pobiera informacje o zmianach ze zdalnego repozytorium, ale ich nie scala.
git branch Wypisuje lokalne gałęzie. Użyte z nazwą tworzy nową gałąź.
git switch Zmienia aktywną gałąź (np. git switch main).
git log Wyświetla historię commitów w bieżącej gałęzi.
